## 0.4.0 — 2026-05-29

Minor release. Three packages bumped in lockstep: `bazilion`, `@bazilion/client`, `@bazilion/api-types`.

This release teaches agents to **act on the web and reach external tools** — native Playwright browser automation and an MCP client — and makes file exchange bidirectional across every client.

### Highlights

- **Browser automation (native Playwright).** Agents get a `browser_*` tool suite (navigate, snapshot, click, type, hover, select, fill_form, press_key, go_back, tabs, take_screenshot, console, network) backed by a persistent per-agent Chromium session that survives across turns. Perception is **accessibility-tree-first** — `browser_snapshot` returns an aria tree with `[ref=eN]` element refs, so no vision model is needed; screenshots are a secondary, multimodal escape hatch rendered inline in chat. A network-layer SSRF guard blocks loopback/private targets (override with `BROWSER_ALLOW_PRIVATE_NETWORK` for local dev). Configure on `/config` (Browser Automation) or via env; run `pnpm exec playwright install chromium` once.
- **MCP client.** Connect the daemon to Model Context Protocol servers over stdio (local subprocess), Streamable-HTTP, or SSE (with optional bearer auth). Each enabled server's tools are discovered and injected into every agent turn, namespaced `mcp__<server>__<tool>`. Manage with `bazilion mcp add|list|show|rm|enable|disable|test` or the `/config/mcp` page.
- **Long-lived daemon-side resources over IPC.** Browser sessions and MCP connections don't fit the per-turn worker (fresh subprocess, no state, dies at turn end), so they live in a process-lifetime registry in the daemon (idle-reaped, closed on shutdown) and the stateless worker proxies to them over Node IPC. Tool results are now **multimodal** (text + images).
- **Bidirectional attachments across all clients.** Send any file *in* and receive any file *out*, on web, Telegram, and CLI. Inbound files travel as one generic `Attachment {name?, mimeType, data}`; the daemon classifies each at turn assembly — `image/*` goes to the model as **vision** (pi `prompt({images})`), everything else is **stored under the agent's home and referenced by path** so the agent opens/processes it with its tools. Attach via the web composer (📎 / paste / **drag-and-drop**), a Telegram photo/document/voice, or `bazilion agent chat <id> --image <path>` / `--file <path>`.
- **Outbound files.** Tool-produced images (browser screenshots, MCP image results) surface as first-class deliverables — a standalone image block in the web chat and a photo on Telegram (regardless of mirror mode). Agents send arbitrary files back with a new **`deliver_file`** tool — a download link in the web chat, a document on Telegram, saved to disk on the CLI. 25 MB per file.
- **Audio/video deferred.** pi and every wired provider are text+image only, so non-image media can't reach the model as input yet (it gets a stored file + path) — to be revisited when a provider exposes those modalities.
- **Dependency + model-catalog refresh.** pi `0.75.4 → 0.77.0` (expanded built-in LLM catalog, surfaced automatically by the data-driven `/config` provider list; example hints refreshed to `claude-opus-4-8`, `gpt-5.5`, `gemini-3-pro-preview`, etc.), plus in-range updates across the tree.

## 0.3.0 — 2026-05-28

Minor release. Three packages bumped in lockstep: `bazilion`, `@bazilion/client`, `@bazilion/api-types`.

This release is all about **Telegram**. Bazilion can now run a Telegram bot that gives each agent its own forum topic inside a single supergroup, with two-way chat and a dedicated control-plane topic for spawning and managing agents — so you can talk to your agents from your phone.

### Highlights

- **One topic per agent, two-way chat.** Agents live in a Telegram *forum* supergroup: typing in an agent's topic runs a turn, and its reply mirrors back into the same topic with a "typing…" indicator and a 👀 reaction on your message. Messages sent while the agent is busy are queued and answered together. A pinned **⚙ bazilion** service topic is the control plane.
- **Setup + preflight.** Connect a bot token + supergroup chat ID from the web (`/config/integrations/telegram`) or the CLI (`bazilion telegram config set`). A preflight health check verifies bot identity, supergroup reachability, that forum Topics are enabled, that the bot has *Manage Topics*, and that Privacy Mode is off — each failed check comes with a fix hint. Activation is automatic and idempotent (it creates the service topic, posts a directory message, and hides *General* only on first run).
- **Spawn and bind from anywhere.** From Telegram: `/spawn` (interactive or `/spawn <profile> <name>`), `/spawn_team` (whole profile-group team), and `/talk <agent>`. Also from the web agent page (**bind a topic**) and `bazilion telegram bind`. Each agent gets a named topic with a profile-derived icon; per-group name templates (`{agent.name}` / `{group.name}` / `{group.slug}`) control titles and propagate renames.
- **Access control (trust-on-first-use).** While the allowlist is empty the first user to message the bot becomes the owner; everyone else is blocked until allowed. Owners manage members with `/allow` / `/deny` (by numeric id — `/whoami` reveals yours), plus the web **Access control** card and `bazilion telegram allow|deny|allowed`. The last owner can't be removed.
- **Multimodal inbound (bounded).** Inbound photos, documents, and voice are downloaded into the agent's home and referenced by path for the turn, up to Telegram's 20 MB bot-download limit.
- **Resilience.** Per-agent inbound/outbound rate budgets, a per-supergroup outbound send queue with 429 backoff, a polling stall-watchdog that self-restarts, supergroup-migration detection with a one-click **Reconnect**, and lazy reconciliation when a human deletes a topic.
- **Documentation.** A detailed end-to-end Telegram setup guide (including the manual BotFather and forum-supergroup steps) is now published at [bazilion.com/docs](https://bazilion.com/docs/telegram/).

## 0.2.1 — 2026-05-25

Patch release. Fixes a crash in the published `bazilion@0.2.0` npm package — `npx bazilion serve` exited with `ERR_MODULE_NOT_FOUND: Cannot find package 'sqlite'` before the daemon could bind a port. No source-code changes; the bug was entirely in `apps/cli/tsup.config.ts`.

### Highlights

- **`node:sqlite` prefix preserved in the bundle.** esbuild's hardcoded known-builtins list predates `node:sqlite` (Node 22+). It auto-externalizes `node:` imports before plugin `onResolve` hooks can intercept them and strips the prefix at print time — so `from 'node:sqlite'` shipped as `from "sqlite"` in the bundle, which Node tried to resolve from `node_modules` and failed. There's no esbuild flag to force-keep the prefix; the fix is a post-build string replace in tsup's `onSuccess` hook.
- **SQL migrations staged into `dist/migrations/`.** `migrate.ts` reads them relative to `import.meta.url` (i.e. `dist/migrations/` at runtime), but tsup only emits JS — the `.sql` files were never copied. The same `onSuccess` hook now copies `apps/daemon/src/core/db/migrations/*.sql` into `dist/migrations/`. The published 0.2.0 had this bug too; the sqlite crash just masked it.

Verified with a clean `BAZILION_HOME`: `node dist/cli.js serve` boots, auto-bootstraps `~/.bazilion`, writes `auth.json`, listens on the port, and `/api/health` returns 200.

## 0.2.0 — 2026-05-25

Minor release. Three packages bumped in lockstep: `bazilion`, `@bazilion/client`, `@bazilion/api-types`.

### Highlights

- **Profile Groups (BAZ-002).** Preconfigured team templates that spawn N agents into a target group in one atomic call. A profile group is an ordered list of members, each pointing at a profile with optional per-member overrides (`agent_name`, `model_override`, `reasoning_level`). `spawnProfileGroup` is one transactional call: pre-flight validates every `profileId`, snapshots both `agents/` and `groups/` dirs before the tx, and on any failure cleans the dir-diff with retry-with-backoff. Name collisions auto-suffix `-2`, `-3`, … against agents already in the target group; the target group is auto-created if its slug doesn't exist. New schema: `profile_groups` + `profile_group_members` (migration `0002_profile_groups.sql`).
- **CLI/web/API parity for profile groups.** HTTP: `GET|POST|PATCH|DELETE /api/profile-groups`, `PUT /api/profile-groups/:id/members`, `POST /api/profile-groups/:id/spawn`. CLI: `bazilion profile-group create|list|show|update|edit|delete|spawn`. Web: top-nav `templates` tab (shared with profiles), `/profile-groups` list + detail, sidebar `+ new ▾` two-section dropdown (spawn agent from template / spawn group from template), empty-group CTA on `/groups/:id`. New wire types `ProfileGroup`, `ProfileGroupMember`, `ProfileGroupDetail`, `ProfileGroupWithCount` in `@bazilion/api-types`.
- **Strictly additive spawn paths.** The single-profile `POST /api/agents` spawn path is untouched.
- **Friendlier delete errors.** Deleting a profile that's still referenced by a profile group now returns a readable error instead of a raw SQLite FK violation; the web UI now surfaces daemon errors on profile delete (was silently swallowed).
- **Shared web `<Button>` component.** `variant="primary|ghost|danger"`, defaults `type="button"`. Wraps the existing `.btn-primary` / `.ghost-btn` / new `.danger-btn` classes. Prevents the class of bug where bare `<button type="button">` falls through Tailwind preflight and renders unstyled.
- **Theme flash fix.** Root layout now uses `data-layout` instead of `className` so the pre-paint `.dark` class survives React reconciliation when navigating to/from `/`.

## 0.1.1 — 2026-05-23

Patch release. Three packages bumped in lockstep: `bazilion`, `@bazilion/client`, `@bazilion/api-types`.

### Highlights

- **Shared USER.md editing for agents.** Agents in a group can now update the shared USER.md via new `user_md_get` / `user_md_write` tools with optimistic-etag concurrency control. Previously read-only. USER.md is capped at 12 KB (inlined into every system prompt). `UserMdHost` joins `MessagingHost` as a daemon-side RPC surface, so the worker still doesn't need a SQLite handle.
- **Provider expansion.** Migrated the underlying [pi-ai](https://www.npmjs.com/package/@earendil-works/pi-ai) package from the `@mariozechner` scope to `@earendil-works`. New providers wired up: DeepSeek, Fireworks, Together, Moonshot AI, Kimi Coding, MiniMax, Xiaomi MiMo, OpenCode, GitHub Copilot, Cloudflare AI Gateway, Cloudflare Workers AI, and a self-hosted llama.cpp endpoint (set `LLAMACPP_URL`).
- **Web fetch tool hardened.** `@mozilla/readability` + `linkedom` extraction with markdown output, SSRF guard with DNS-rebinding re-validation pinning resolved IPs into undici's connect-lookup, 15-min LRU per `${mode}|${url}` (100-entry cap), desktop-Safari UA, 20s timeout, 3 max redirects.
- **Web UI polish.** Services config page, root chat layout, theme tokens, `FieldRow` component refresh.
- **Backlog system.** Two new draft items landed under `docs/backlog/draft/`: [BAZ-002 Profile Groups](docs/backlog/draft/BAZ-002-profile-groups.md) (preconfigured team templates) and [BAZ-003 Hermes-style self-learning loop](docs/backlog/draft/BAZ-003-hermes-self-learning.md) (background reviewer + skill self-editing, modeled on Nous Research's hermes-agent).

## 0.1.0 — 2026-05-22

Initial public release. Three packages published to npm in lockstep:

- **`bazilion`** — CLI + bundled daemon. End-user package; `npx bazilion serve` boots the local stack on `127.0.0.1:4321`.
- **`@bazilion/client`** — hermetic HTTP client for the daemon (zero node-only deps; runs in browsers, React Native, edge runtimes).
- **`@bazilion/api-types`** — zero-dep TypeScript wire types for everything that crosses the HTTP/IPC surface.

### Highlights

- **Multi-agent local runtime.** The daemon is the single owner of `~/.bazilion/` — SQLite DB, agent homes, group collaboration roots, skill library, encrypted secrets. Self-bootstraps on first `bazilion serve`; no separate init command.
- **Profiles → agents → groups.** Profiles are templates. Agents are instances spawned from a profile into exactly one group. A group is a collaboration context: one filesystem root, one `USER.md`, one roster, one shared memory.
- **OpenClaw-compatible skills.** Drop a `SKILL.md` under `~/.bazilion/skills/<name>/`, or bulk-import via `bazilion skill import --from openclaw`. The body is injected into the system prompt of every agent it's attached to.
- **Provider coverage via [pi-ai](https://www.npmjs.com/package/@earendil-works/pi-ai).** Anthropic, OpenAI (API key + ChatGPT OAuth for `gpt-5.x` / `gpt-5.x-codex`), Google AI Studio + Vertex, Azure OpenAI, AWS Bedrock, Mistral, Groq, Cerebras, xAI, Z.AI, Hugging Face, OpenRouter, Vercel AI Gateway, LM Studio, Ollama.
- **Group-shared BM25 memory** via [qmd](https://github.com/tobi/qmd). One index per group; every agent in the group reads and writes the same store.
- **Cron + interval triggers.** In-process scheduler. `bazilion trigger add <agent> --every 300 --message "check inbox"` or any 5-field cron expression.
- **Inter-agent messaging.** `send_message` / `read_inbox` / `wait_for_reply` tools, plus out-of-loop surfaces: `bazilion send`, `bazilion inbox`, HTTP routes, web UI inbox page.
- **Whole-run subprocess isolation.** Every chat turn runs in its own Node worker; messaging-tool calls round-trip back to the daemon over Node IPC. Workers don't hold their own SQLite handle.
- **Web UI at `apps/web`** (TanStack Start + React 19 + Tailwind v4 + shadcn/ui). CLI/web parity for every endpoint. Not bundled into the npm package yet — clone the repo to run it.
- **Expo mobile app at `apps/mobile`** for LAN/Tailscale pairing via `bazilion://pair?…` URLs and QR codes.
- **Auth.** One token table; bootstrap token in `auth.json`; per-client tokens via `bazilion token create --qr`; ChatGPT OAuth via `bazilion auth openai login`.

### Requirements

- **Node 24** or newer (native TypeScript type-stripping for the worker subprocess, `node:sqlite` for the DB).
- pnpm 10+ for the source checkout (npm-only consumers don't need it).

### Packaging notes

- All three packages bundle their workspace deps inline at build time via [tsup](https://tsup.egoist.dev/); only the daemon's runtime deps (`hono`, `pi-*`, `qmd`, `@mozilla/readability`, `undici`, …) are externalized so they install at consumer install time.
- Releases publish with [npm provenance attestation](https://docs.npmjs.com/generating-provenance-statements) via GitHub Actions — every version on npmjs.com links back to the source commit it was built from.
