## Narrow remediation implemented

`apps/daemon/src/lib/native-search.ts` now attaches a **closed, secret-safe diagnostic** to
native failures and their canonical error text:

- Phase: admission, credential, request, response body, decode, evidence or disclosure.
- Allowlisted local failure class: connect/header/body timeout, DNS/TLS failure, connection
  reset/refusal, socket error, invalid UTF-8/JSON, generic type/unknown exception, explicit
  refusal or cancellation/deadline.
- Observed numeric HTTP status when available and a closed media category, not raw headers.
- No raw exception message/cause/stack, upstream body, URL, hostname, account identifier or
  credential disclosure. Cause traversal is bounded; own data properties only, so throwing
  accessors/cycles/unknown error codes are not read through or printed.

For example, fake connect timeout now reports
`[phase=request; code=connect_timeout; http=unknown; media=unknown]`, while fake HTTP 200 HTML
reports `[phase=decode; code=invalid_json; http=200; media=other]`. These are fixture examples,
**not reconstructed observations of the failed live trial**.

MIME matching is now normalized and exact, so valid case-insensitive SSE content types reach
the same strict parser. Framing, terminal identity/order, search execution, citation/domain,
byte/deadline and secret-redaction checks remain. No network/account/tool fallback, retry,
new provider admission or relaxation of successful-evidence criteria was added.

Ten new regressions cover safe request/body/decode/credential/evidence diagnostics, mixed-case
SSE and malformed/duplicate framing, private/cyclic/accessor/unknown exception metadata, no
search retry and disclosure filtering. All ten are required by the security acceptance manifest.
