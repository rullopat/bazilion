## Implemented boundaries

- `lib/ordinary-search-config.ts`: one deterministic disabled/explicit/Brave/SearXNG/current-Agent
  native/unavailable decision; official endpoints, narrow pinned model protocol subset, selected
  account and mode, truthful configuration-only status. No cross-provider automatic route.
- `lib/native-search.ts`: query-only hosted `web_search`, no auxiliary Agent/shell/files/browser/
  MCP/peer host; 512 chars, 1–8 citations, 30 s deadline and absolute-time recheck, incremental
  2 MiB upstream/32 KiB output/2 KiB normalized URL bounds, no search retry/fallback. Requires
  completed search action, successful same-model terminal response, consistent SSE identity/
  delimiters/DONE ordering and citation annotations. Returned usage is observed, mode unknown.
- `lib/ordinary-web-search.ts`: daemon-only credentials, captured API/Brave key identity and
  subscription account identity, same-account OAuth refresh, live drift/cancellation checks,
  decoded string-leaf/URL secret filtering including bootstrap protection, one in-flight search.
- Configured ordinary turn → worker IPC → tool composition; native evidence is retained in
  canonical Pi `details.webSearch`. Unadmitted host means no hidden/env-backed search tool.
  Protected BAZ-067 discovery remains separate; ordinary-host attachment to protected/restricted
  workers is denied before spawn. No new scheduled/inbox/review/verification admission.
- Ordinary `web_fetch` details distinguish direct requested/effective URL/status/time, cache and
  truncation. Firecrawl content carries **unknown local source URL/status**, separate direct-fetch
  and bounded provider-reported provenance. Rendered content never inherits the direct receipt.
