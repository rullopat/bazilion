## Approved contract and implementation

- Owner-only inventory exposes opaque capture ID, original Team/producer, capture time and byte
  count, with quota totals. No filename, prompt, model, hash, source or image/preview bytes.
- Explicit immutable-ID recovery validates completed-capture qualification, deletion and original
  membership. It refuses active, missing, archived or transferred producers; no substitute producer.
  It reuses the existing Result-library authorizer, stable `result_publication` identity and
  reference-only `agent_result` approval—not another authorization path, model or Agent turn.
- Current policy can release, deny or hold. A repeated pending library request returns the existing
  approval; another transport's hold is not rerouted. Closed attempts stay closed, even after policy
  changes; the approval dispatcher retains its normal revalidation and at-most-once semantics.
- Explicit confirmed discard tombstones eligible private bytes without disclosure, preserving the
  completed generation receipt. It refuses active producers and pending/approved/delivering holds.
  Missing/archived/transferred producers may still be discarded by the original-Team owner.
  Released files use normal Results deletion. Deleted content never regenerates or resurrects.
- CLI commands are `result private-images`, `result recover-image`, and `result discard-image --yes`,
  with original `--team` required. The Team Results page has matching inventory/recovery controls
  and a destructive confirmation dialog. Normal previews/downloads/source stay unavailable until
  release. Owner browser writes retain session-bound CSRF through the existing gateway.

One shared SQL witness identifies completed image captures for retention and management. No schema,
provider/SDK, generation retries, worker capability, system/Docker setting or account was changed.
Images can remain disabled/logged out while an eligible stored capture is recovered. Storage failure
before atomic commit, deleted bytes and closed delivery attempts are not recoverable by this path.
