## Dirty-input disposition is an open gate

The inventory is **preservation and identity, not blanket inclusion approval**. Existing dirty work
was not reset, restored, staged or silently discarded. Before calling this a final candidate,
review every changed-path entry as **include with rationale/evidence**, **defer while preserving**,
or **hold for decision**. No changed implementation input is implicitly waived by a story being Done.

Pay particular attention to shared changes beyond the four story labels:

- Embedded Pi 1.0.0 and standalone MCP integration/retirement, tool admission, worker output and
  process ownership, provider routing, lockfile and package/build policy.
- Managed browser launch/proxy/profile/observation lifecycle and backup exclusion.
- Backup, paths, uninstall/reset and filesystem ownership; CLI/client/API/web parity.
- Canonical `0001_init.sql`, MCP transport retirement and prior-home/backup refusal semantics.
- Recipe/protocol documentation, removed story files and the remaining untracked source/tests.

These are not new feature requests. Their disposition and regression coverage are necessary to
avoid shipping unreviewed bytes or omitting load-bearing dependencies. If an input cannot be
attributed safely, stop for a scope decision; do not manufacture a smaller green candidate.
