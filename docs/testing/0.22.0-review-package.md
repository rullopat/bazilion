## Change 1 — worker-exit defect fix (patch) — ACCEPTED (operator, 2026-09-21)

**File:** `apps/daemon/src/runtime/worker/entry.ts` (+31 lines vs HEAD, including BAZ-059's host
wiring already in that file; the fix itself is 4 lines in `main()`):

```ts
  // The turn is complete: session disposed, IPC disconnected. Some underlying
  // handle (native store/provider socket) can otherwise keep this process alive
  // for tens of seconds after its work is done, holding the Team workspace
  // lease and blocking every interleaved turn on it. Exit explicitly instead.
  process.exit(process.exitCode ?? 0)
```

- **Defect:** a worker whose turn ended (success or failure) could linger ~30s on a lingering
  handle while holding the Team's exclusive workspace lease; interleaved turns got
  `workspace_busy`. Measured root cause: `ps --ppid <daemon>` showed the child alive the whole
  window; all daemon-side release paths run in <1 ms once called.
- **Why explicit exit is safe here:** the finally block has already unsubscribed listeners, disposed
  the session, and disconnected IPC; the error path already used an explicit `process.exit(1)`.
  The daemon treats the exit event (not lingering output) as the turn end — `spawn.ts`'s generator
  completes `waitForExit`/`stderrTask` before the lease release.
- **Risk:** if any future worker work legitimately outlives `main()` (background timers), it will be
  cut off. Today nothing does: all post-turn work happens daemon-side.
- **Changeset:** `.changeset/baz-064-worker-prompt-exit.md` (patch).
- **Evidence:** the harness test asserts the lease frees within 5s (previously 30s); full suite,
  Docker image/crash suites and security acceptance re-run clean after the change.

## Change 2 — BAZ-067 bounded protected web discovery (minor) — ACCEPTED (operator, 2026-09-21), repositioned as the opt-in protected-turn backend; default search is BAZ-069's browser-backed story

**Files (9):** new `apps/daemon/src/lib/web-search.ts`; `ipc-protocol.ts`, `worker/runtime.ts`,
`worker/spawn.ts`, `worker/entry.ts` (host plumbing), `runtime/tools/web.ts` (tool),
`runtime/pi/tools.ts` + `runtime/pi/session.ts` (projection), `lib/agent-turn.ts` (wiring).
Plus `security/acceptance-manifest.json` (the projection test renamed) and tests
(`apps/daemon/test/lib/web-search.test.ts`, integration in `apps/cli/test/content-team-research.test.ts`).

**Behavior:** a protected turn includes `web_search` only when the operator configured
`BAZILION_WEB_SEARCH_URL` (self-hosted SearXNG, https or loopback http). The worker gets an
IPC-backed host — never the URL/credentials. Bounds: ≤512-char query, ≤8 results, capped fields,
one request per invocation, 15s deadline + cancellation, no retry/fallback; the URL is re-validated
per request (drift refused). Restricted workers are denied at `spawnHosts`. Returned URLs are
untrusted data; fetching goes through the SSRF-guarded `web_fetch`.

**Directional decision 2026-09-21 (operator):** Bazilion's *default* search experience should be
browser-backed (real Chromium via the existing pool — the OpenClaw approach), tracked as
[BAZ-069](../backlog/draft/BAZ-069-browser-backed-default-web-search.md). SearXNG-by-default was
judged a mistake; defaults must work, and SearXNG/Brave remain operator opt-ins. BAZ-067 is
repositioned as the **opt-in protected-turn** discovery backend — its implementation, bounds and
verification are unchanged. The four questions below remain formally open for the operator's
confirmation; the directional decision implies (but does not yet record) env-only config for beta,
accepted ordinary-path asymmetry with a migration note, env-only documentation, and accepting the
manifest rename.

**Review questions — CONFIRMED by the operator 2026-09-21 (Change 2 ACCEPTED):**

1. **Env-var config accepted for beta.** Discovery is an opt-in advanced feature; config/DB + UI
   parity is deferred (candidate follow-up with the BAZ-069/config work).
2. **Ordinary-path asymmetry accepted.** The ordinary `web_search`'s direct env credential access
   is unchanged since 0.21 (no regression); its real story is BAZ-069's browser-backed default,
   and a later migration of the ordinary path to the daemon-host pattern is recorded intent there.
3. **Env-only documentation for beta.** No `/config` readiness display now; UI visibility belongs
   with the deferred config-parity work.
4. **Security-manifest rename accepted.** The projection test's name truthfully tracks the closed
   set gaining `web_search`; case ID, required count and assertions intact.

**Changeset:** `.changeset/baz-067-protected-web-discovery.md` (minor).
**Evidence:** 8 host unit tests; scoped-projection tests (absent without host / present with it /
restricted denial shape); integration: a protected researcher wake searching a test-owned loopback
