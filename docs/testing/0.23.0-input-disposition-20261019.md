## H1 — conflicting package-manager selection

**Held path:** `mise.toml` (line 3).

It selects `pnpm = "12.14.0"`; root `package.json` pins **`pnpm@11.14.0`**, and installed inspection
reported 11.14.0. PR CI uses pnpm/action-setup with the repository package-manager input. The freeze
recorded both source and observed runtime; it did not establish that the conflicting selection works.

**Recommended decision:** retain the root/CI 11.14.0 train and align only mise's pnpm selection.
Preserve the current local Node selection; Node 24 CI qualification remains separate. Do not install
another manager, rewrite the lockfile or silently approve a package-manager upgrade here. If 12.14.0
was intentional, request an explicit broader toolchain/version/requalification decision instead.

## H2 — unsafe operator remedy in otherwise fail-closed uninstall

**Held path:** `apps/cli/src/commands/uninstall.ts`, currently lines **93, 102 and 115**.

The new browser owner checks refuse unreadable/corrupt/unknown markers, but the associated error
messages recommend **“remove the slot manually”**. That conflicts with
[the canonical browser contract](../browser-research.md): unknown/interrupted ownership is recovery
required, not permission to remove the profile, owner marker or singleton lock. This is a reachable
operator-guidance conflict, **not** evidence that the command automatically deletes an unknown slot.

**Recommended bounded correction:** replace those manual-removal remedies with truthful supported
operator diagnostics/stop guidance and an explicit instruction to leave state intact if ownership
cannot be established. Preserve the existing refusal, exclusive-ownership recheck and all no-force-
clear/no-Agent-recovery boundaries. Add/recheck fixture-only CLI regression assertions for those
messages before clearing this hold. No original home, real browser, daemon restart or ownership
acknowledgement is authorized by this attribution step.

This is a source-attribution concern found by the implementing assistant, not a fresh independent
security verdict or permission to waive the contract. Do not proceed to versioning/qualification by
omitting this load-bearing browser-safety change without a separately reviewed candidate assembly.
