## What the publishers actually say

The official [Node release index](https://nodejs.org/dist/index.json), observed2026-10-20, lists
installed v24.20.0 (2026-08-26) and current24 LTS v24.22.0 (2026-10-14), both ABI137.

[Node24.22.0](https://nodejs.org/en/blog/release/v24.22.0) and
[Node26.4.0](https://nodejs.org/en/blog/release/v26.4.0) release notes each list
**“src: keep global list of addon-provided cleanup hooks”**, referencing
[upstream PR63985](https://github.com/nodejs/node/pull/63985).
The upstream explanation says the API incorrectly assumed a Node Environment would always be
associated with the current Isolate/Context when `RemoveEnvironmentCleanupHook()` runs; that can
break during garbage collection. It states that the change resolves this through a global list
while preserving Node’s within-major API/ABI contract.

That explanation directly matches the recorded native callee/assertion and GC mechanism. It is
strong evidence for **testing the upstream runtime fix**, not proof that Bazilion’s original worker
caller is identified or that an untested runtime/artifact is qualified. The PR top state is “Closed”;
it is not promoted into a merge assertion. The independent official release-note listings establish
that the named change is included in those releases.

The [24.x ObjectWrap history](https://github.com/nodejs/node/commits/v24.x/src/node_object_wrap.h)
records a2026-07-30 cleanup-hook addition. That alone does not prove which other patch releases are
affected. Built-in `node:sqlite` changes in Node’s release notes are not mistaken for a
better-sqlite3 fix.

The [better-sqlite3 release page](https://github.com/WiseLibs/better-sqlite3/releases) describes v13’s
N-API rewrite. No major driver upgrade, override, vendoring or compatibility claim was selected.
The existing dependency graph and Pi1.0.0 pin remain unchanged.
