## Corrections within the approved harness-hardening scope

- **P1, destructive uninstall after an earlier failure:** `runGuardedUninstall()` now refuses any
  accumulated functional failure and requires acceptance of **all preceding owned-close outcomes**
  before calling uninstall. Actual forced retirement is abnormal and holds that callback. The
  successful uninstall status/paired-file-removal oracles remain unchanged. Final teardown still
  attempts owned closes when assertions fail; it does not erase the primary diagnostic home.
- **P2, retained report claiming success after root removal failed:** a shared finalizer first saves
  `passed:false` with removal `pending` (or `retained` for failed checks), then records `removed` or
  `failed`, including the actual error. Success is recorded only after the removal callback returns.
  The installer pins an exclusively created mode0600 evidence descriptor across these writes; it
  does not reopen/truncate an unowned path. Initial write failure prevents removal, without retry.
  A final evidence write failure fails the invocation; it cannot restore a fixture already removed.
- **P2, unbounded SSR response:** SSR reads now have a256KiB byte ceiling and cancel/release the
  reader on completion/error, preserving the existing HTTP200/content oracle and two-second fetch
  signal. Health reuses the same reader with its existing4096-byte ceiling.
