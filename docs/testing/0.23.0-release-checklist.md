**Publication boundary:** `.github/workflows/release.yml` runs on pushes to `main`; Changesets can
publish when no pending changesets remain and versions are ahead of npm, and pushes package tags.
A merge/push/version PR or workflow invocation may therefore be an external side effect, not harmless
preparation. No such action is authorized by the freeze request.

Only after that approval: observe actual npm/provenance/package-tag results, verify exact published
installation, create the authorized umbrella release at its exact commit, fill release metadata and
deploy reviewed website changes. Never blindly retry an interrupted publication.

## Change control

For an input/version/code correction: preserve first failures, record a freeze amendment/new source
identity, rerun affected gates and rebuild/requalify final artifacts. Missing composed/live/human work
stays openly deferred; it is not a way to waive a critical safety or core-task failure in this slice.
