## Bounded correction

After selecting mise's pnpm 12.14.0, the operator requested the next release task. The stated task
was correcting uninstall guidance and running focused offline fixtures, not changing ownership
behavior, starting an original daemon, expanding recovery or running the whole release campaign.

`apps/cli/src/commands/uninstall.ts` now uses one safe remedy for unreadable, corrupt, unknown and
live browser ownership: leave the profile, owner marker and lock files untouched; use supported
browser status/stop controls; keep uninstall blocked and seek operator support if ownership remains
uncertain. It no longer recommends manual slot deletion, a supposedly curative daemon restart,
or manual termination of a guessed browser. Supported status/stop is not promised to resolve an
unknown marker or establish safe ownership by itself.

No process identity, ownership predicate, signal, destructive target, prompt, exclusive-lock
recheck, delete operation or completion acknowledgement changed. The source from
`function markerOwnerPresence` through the end of the command is byte-identical to the pre-fix
source; its digest is retained with the proof. Earlier ownership-check branches changed their
error text only. There is no force-clear, new Agent/HTTP recovery path or abnormal-host guarantee.
