## Change

The Results reconciler previously reclaimed a private capture as soon as its producer disappeared
and no live approval referenced it. That included a completed image committed before worker ACK.
The repair excludes only captures whose **source kind, Agent, original Team, session, tool call and
image model match a completed durable image operation**. Metadata alone, failed/uncertain operations
and mismatched identities do not preserve an ordinary orphan. No schema, provider/SDK, IPC, API,
authorizer or replay behavior changes. Existing Results quota still counts retained private bytes.

Retention does not release an image: private metadata, download and preview remain404, pending or
denied delivery still cannot disclose bytes, and deletion tombstones remain final. Ordinary-file
reclamation is unchanged. The scope intentionally retains completed image captures even without a
live delivery/approval; storage remains bounded by the existing1GiB/home limit.

## Remaining product gap and release applicability

Retaining bytes is not complete recovery. A capture with no surviving delivery attempt is still
absent from owner-facing Results; no new operator action can discover, authorize delivery or discard
that private capture. Hidden retained bytes also consume quota. The repair does not add a recovery
UI/CLI/API, auto-release anything, invent an approval, or promise recovery after pre-commit storage
failure. An explicit recovery/discard path through the existing shared authorizer needs a bounded
follow-up decision/design before claiming the user-facing loss problem fully resolved.

All existing tarballs remain immutable evidence of their earlier source. **The old CLI tarball does
not contain this repair** and cannot qualify the changed application; rebuild/repack and installed
qualification will be needed before publication. No source commit/push, release or website change
occurred. The goal's conditional release authority and homepage no-Pi-version requirement remain.
